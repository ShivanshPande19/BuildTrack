# Native setup (camera, photos, deep links)

`app/android/`, `app/ios/` and `app/web/` are generated by `flutter create .` and **are tracked in
this repo**, so a fresh clone builds without re-doing any of the setup below. Nothing here touches
`lib/` or `pubspec.yaml`.

They were untracked at first, which meant a clone of this repo could not be built by anyone but the
author. Everything in this file is therefore a record of edits **already committed** — read it to
understand *why* a permission or a version floor is there, not as a checklist to re-apply.

Two things stay out of the repo on purpose (see `.gitignore`):

- **`app/android/key.properties` and any `.jks` / `.keystore`** — release signing. A leaked keystore
  lets anyone ship an update that Android accepts as genuinely from Azimuth. These live on the
  release machine only.
- **Generated output** — `app/ios/Pods/`, `Flutter/Generated.xcconfig`, `.gradle/`,
  `local.properties`, etc. `flutter pub get` and `pod install` recreate them.

`pubspec.lock` and `ios/Podfile.lock` **are** committed, so every machine and CI resolve the same
dependency versions.

Deep links for member invites are covered separately in [`INVITE_FLOW.md`](INVITE_FLOW.md) §3–4.

## Why these are needed

| Feature | Package | Needs |
|---|---|---|
| Workshop site photos · client ticket photos | `image_picker` | camera + photo library access |
| Scan a part's QR/barcode to install it | `mobile_scanner` | camera access |

Minimums the packages themselves require: **Android `minSdk` 23**, **iOS 13** (`image_picker_ios`
needs 13.0; `mobile_scanner` itself allows 12.0, so 13 covers both).

---

## 1. Android — `android/app/src/main/AndroidManifest.xml`

Add above `<application>`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.INTERNET" />
```

`INTERNET` is added automatically for debug builds but **not** for release — without it a release
build cannot reach Supabase at all.

Gallery picking needs no permission on modern Android: `image_picker` uses the system photo picker.

### `android/app/build.gradle.kts`

`mobile_scanner` requires `minSdk` 23. Recent Flutter templates already default higher, but if yours
is pinned lower, raise it:

```kotlin
defaultConfig {
    minSdk = 23
}
```

---

## 2. iOS — `ios/Runner/Info.plist`

Add inside the top-level `<dict>`. iOS **rejects the app at review** without a usage string, and the
permission prompt shows this text, so make it specific:

```xml
<key>NSCameraUsageDescription</key>
<string>BuildTrack uses the camera to scan part barcodes and take build photos.</string>

<key>NSPhotoLibraryUsageDescription</key>
<string>BuildTrack lets you attach photos of your build or of an issue you are reporting.</string>
```

### `ios/Podfile`

Ensure the platform is at least 13:

```ruby
platform :ios, '13.0'
```

Then `cd ios && pod install`.

---

## 3. Web (optional)

Both packages work on web, but the camera only works over **HTTPS** (or `localhost`). On plain HTTP
the browser blocks `getUserMedia` and the scanner shows its "camera not available" state.

## Verifying it works

1. **Workshop → a task → Photo** — the camera/gallery sheet appears, the photo previews, and after
   upload it shows on the client's stage timeline (it is a real file in the `builds` bucket now, not
   a `picsum.photos` placeholder).
2. **Workshop → scan button → Scan serial** — the viewfinder opens with a torch toggle. Scanning a
   part's label finds it by serial; **Enter serial manually** is the fallback for a damaged label.
3. **Client → Raise a request → Add a photo** — attaches to the ticket, and Service sees it under
   *Photos from the client* on the ticket.

If the camera screen shows "Camera not available", the permission was denied or the usage string is
missing — the manual-entry path still works.

## Storage

Photos go to the public **`builds`** bucket, created by
[`supabase/migrations/0011_builds_storage.sql`](../supabase/migrations/0011_builds_storage.sql):

- staff write anywhere in the bucket (`stages/<stageId>/…`)
- a client may only write under `tickets/…`
- public read, so the app loads them straight from the stored URL
